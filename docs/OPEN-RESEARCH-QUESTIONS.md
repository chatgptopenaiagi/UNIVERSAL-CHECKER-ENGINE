# Open research questions

[Return to README](../README.md)

These questions define possible investigations, not work initiated by UCE-001. The proposed methods below would require their own scope and authorization where they involve implementation, participants, external systems, or state changes.

| Question | Why it matters | Possible future investigation and useful evidence |
|---|---|---|
| Which concepts transfer between domains? | Reuse can become misleading when similar labels hide different claims | Compare independently designed checker descriptions; record shared concepts and irreducible exceptions |
| Should outcomes use several dimensions? | Connectivity, identity, permission, and verification can coexist | Review ambiguous scenarios with domain experts; assess interpretation consistency |
| What qualifies as independent verification? | A readback can repeat the same cached or faulty assertion | Analyze common-source failures and compare observation methods; document residual uncertainty |
| How should freshness be communicated? | Evidence loses relevance at different rates | Compare task-specific freshness assumptions and user interpretation of stale results |
| What does one button safely include? | A convenient interaction may hide cost, disclosure, or changes | Evaluate proposed consent flows and scope descriptions before any active experiments |
| How should partial outcomes be summarized? | A green summary can hide excluded or failed checks | Study whether readers identify coverage, uncertainty, and the task's actual blockers |
| How can languages preserve technical distinctions? | Familiar translated words may merge different concepts | Conduct terminology review and comprehension studies across selected languages |
| What evidence can be safely exported? | Reproducibility can conflict with confidentiality | Compare redacted report designs and record which claims become less independently inspectable |
| How should platform limitations be represented? | Unsupported interfaces and denied permissions require different explanations | Compare capability descriptions across selected environments without assuming equivalence |
| How could extensions remain trustworthy? | Shared labels do not ensure sound methods or safe behavior | Investigate review, provenance, permission disclosure, and compatibility practices |
| How should definitions evolve? | Changing a meaning can invalidate comparison with older reports | Review versioned conceptual scenarios and document compatibility or migration requirements |
| What would demonstrate reduced duplication? | More abstraction can create more maintenance work | Compare actual design and maintenance effort in a separately authorized experiment |
| Who governs names and claims of conformance? | Independent applications may interpret the blueprint differently | Develop governance options and distinguish self-description from independently assessed conformance |
| What licensing is appropriate? | Public visibility alone does not define reuse rights | Have the owner choose documentation and any future implementation terms explicitly |

## Prioritization

The earliest questions should concern semantic clarity and evidence: can two people interpret the same result consistently, and does the observation support the claimed scope? Packaging or ecosystem infrastructure would be premature if those questions remain unresolved.

A useful research record would include the hypothesis, selected scenarios, participants or observing environments where relevant, method, observations, counterexamples, limitations, and resulting conceptual revisions. Negative findings should remain available. See [roadmap](FUTURE-ROADMAP.md) and [limitations](LIMITATIONS-AND-CHALLENGES.md).
